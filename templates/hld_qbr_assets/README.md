# HLD QBR Template Asset Tree

Machine-readable grounding layer for `HLD QBR Template PFv3.potx`, generated
by `templates/extract_hld_qbr_assets.py`. This is NOT hand-authored — re-run
the script after the source .potx changes.

## Layout
- `metadata/slide_NN.json` — per-slide structural record: every shape's
  geometry, placeholder type, text runs (font/size/color), chart/table
  structure, and an `is_guidance_sticker` flag on text that matches the
  same authoring-artifact regex the real builder strips at render time.
  Also includes `canvas` (slide dimensions), `structure` (shape/image/
  table-or-chart/annotation counts), `annotation_shapes` (guidance-sticker
  shapes pulled into their own traceable list), and `editable_mapping`
  (this slide's layout + master placeholder inheritance — idx/type/
  geometry, grounded facts from python-pptx, not an invented size/
  orientation label).
- `metadata/manifest.json` — flat per-slide summary (id/title/layout/
  category + the `structure` counts above) for a quick cross-slide scan
  without opening every `slide_NN.json`.
- `inventory/slide_index.json` — flat catalog (index/title/layout/category).
- `inventory/layout-feature-inventory.md` — same flags as a quick-reference
  table (layout/category/has_table/has_chart per slide).
- `inventory/archetype_catalog.json` — `llm/hld_qbr_layout_registry.py`
  archetypes cross-referenced to their source slide index. Retired/legacy —
  not used by the generic pipeline, kept only for the old fixed-archetype
  builder (`core/builders/hld_qbr_builder.py`).
- `inventory/layout_capability_catalog.json` — generic, auto-derived slot/
  table/chart/repeat-group schema per fillable slide (see
  `templates/build_hld_qbr_layout_catalog.py`). It contains no template title
  or sample text: only geometry and capacity can drive topic-to-layout
  matching. Do not use `archetype_catalog.json`'s fixed list for generation.
- `inventory/asset_manifest.json` — generated file/byte counts per folder.
- `brand-assets/source-xml/` — verbatim `slideMaster`/`slideLayout` XML.
- `media/` — real photo/logo raster files (`.jpeg`/`.png`) pulled from
  `ppt/media/`.
- `brand-assets/decorative-media/` — the rest of `ppt/media/` (`.emf`/`.svg`
  status dots, dividers, small decorative glyphs — not real photos).
- `layouts/slide_NN.svg` — full-slide vector SVG per slide, de-sampled
  (guidance-sticker text blanked). Generated by Phase 2, see
  EXTRACTION_NOTES.md and `templates/extract_hld_qbr_phase2_render.py`.
- `brand-assets/icons/set_N_icons_*/icon_NNN.png` — individual icons cropped
  from the icon-library slides (`slide_54`-`slide_56`). Also Phase 2. Folder
  names are purely positional (matching the deck's own "ICONS 1-60" style
  labels) — these 183 shapes have no thematic grouping in the source
  template, so no semantic category name is used.

## Narrative documentation (adapted from a verified reference extraction)

These mirror the sibling TechM-template convention, adapted to this template's actual content and to
this repo's 0-indexed `slide_NN` naming:

- [`slide-inventory.md`](slide-inventory.md) — one row per slide (`slide_00`-`slide_59`): title,
  layout, category, table/chart flags.
- [`guardrails.md`](guardrails.md) — verbatim rules from the template's own "GUARDRAILS" slide
  (`slide_42`), plus derived rules for this project's generation pipeline.
- [`guidelines.md`](guidelines.md) — visual/construction rules from the template's own "FORMATTING
  HELP" section (`slide_41`-`slide_50`): fonts, colors, table/process-flow conventions.
- [`design-tokens.json`](design-tokens.json) — brand color palette and fonts, read from the theme XML
  and `slide_43` ("Brand Approved Colors").
- [`chart-table-specs.md`](chart-table-specs.md) — every real data table's column schema (for human
  orientation only — the runtime catalog exposes counts, not header text), plus the KPI cost-avoidance
  formula recovered from `slide_35`'s speaker notes.
- [`image-icon-rules.md`](image-icon-rules.md) — how to use the four icon sets in this template.
- [`quality-checklist.md`](quality-checklist.md) — pre-delivery checks for the asset tree and its
  automated equivalents in the generation pipeline.
- [`master-footer-inventory.md`](master-footer-inventory.md) — which of the 19 layouts/2 masters are
  actually used by this deck's 60 slides.

**Correction note:** `slide_53`, `slide_58`, and `slide_59`'s titles (and `slide_58`/`slide_59`'s
underlying icon-set folder names) were previously mis-transcribed by an earlier extraction pass —
corrected after cross-checking a verified reference extraction of the same source `.potx`. See

brand-color constant was also corrected (`008575` → `00857D`) to match the deck's real theme value and

## Regenerating
1. `python templates/extract_hld_qbr_assets.py` (Phase 1 — wipes and
   rebuilds this whole tree from the zip/python-pptx, no renderer needed)
2. `python templates/extract_hld_qbr_phase2_render.py` (Phase 2 — needs
   desktop PowerPoint + pywin32; reads Phase 1's metadata/ for icon crop
   boxes, so always run Phase 1 first)
3. `python templates/build_hld_qbr_layout_catalog.py` (rebuilds
   `inventory/layout_capability_catalog.json` from Phase 1's metadata)

The 8 narrative docs above and `inventory/layout-feature-inventory.md` are hand-authored (not
regenerated by the scripts) — re-verify them against `inventory/slide_index.json` after any Phase 1
re-run in case the source `.potx` itself changes.
